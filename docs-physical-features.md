# Offline emitted target work

`ink_planner.physical_features` consumes optional `ink-target-work-v1` sidecars.
`python -m ink_planner.physical_selection` ranks already admitted and emitted DB
alternatives. The ordinary semantic search, its default costs, the semantic
checker and all target selection defaults remain unchanged.

The sidecar binds exact original/selected core, ordinary selection package,
emitted artifact, diagnostic instrumentation, producer/runner and fixture/trace
bytes. Hashes associate observations; the ordinary kernel still checks every
selected law and application from the explicitly supplied immutable snapshot.
The first selector additionally reproduces the exact selected core and emitted
JavaScript bytes. Other target observations can use the same component schema;
the selector retains the baseline until that target's independent artifact replay
is implemented. Missing observations, incomparable cohorts and unknown required
work retain the baseline. Models cannot supply application premises or lowering
correctness. The returned ordinary package must still be checked by its consumer.

The selector captures the input core, candidate index, price model and each
selection package before use. Every candidate replays against the same private
core snapshot, and publication uses the captured selection bytes rather than
rereading caller-owned files after ranking. The receipt hashes the exact captured
inputs. This binds offline ranking to its checked inputs; consumers must still
perform ordinary selection replay. Concurrent replacement tests exercise both
ranked selection and the missing-observation baseline fallback.

Trace and instrumentation JSON are parsed from the same bounded byte snapshots
whose digests were authenticated, including captured-boundary receipts. Replacing
those files after authentication cannot substitute different metadata. Malformed
nested objects reject the observation so the selector can retain its baseline.

Seven separate components are supported: `invocations`, `loop_iterations`,
`allocation_events`, `copy_bytes`, `gpu_dispatches`, `upload_bytes`,
`readback_bytes`. Counts are bounded integers. Required price coefficients are
finite nonnegative nanosecond numbers, including fractional values; booleans,
nonfinite numbers, extra authority fields and out-of-budget inputs are rejected.
Target, host, boundary, emitter bytes and entry ABI must match exactly. Cohorts
never pool C with Rust, native with Wasm, owned with caller destination, or CPU
with GPU. Even a zero-priced required component must be known.

These are deliberately narrow literal observations. Loop iterations count entered
emitted loop bodies and actual native map/filter callback visits, including a body ending in `break`, `continue` or return;
they are not condition checks, backedges, machine instructions or a vectorization
measurement. JavaScript allocation events count completed emitted array carrier
construction operations, not V8 allocator calls, storage bytes or internal
capacity growth. Typed explicit copies have known byte extents; ordinary Array
slice bytes and opaque/custom method traversal remain unknown. Standard native
map/filter, reduction, short-circuit search and explicit sort/factory callbacks
are observed with their original this/arguments and actual entry visitation.
Array and typed-array factories count completed carrier construction. Default
sorting and factories without observable callbacks mark traversal unknown; no
iteration count is inferred from output length. Same-type typed-array `from`
without a mapper records explicit payload copies; conversion and Array bytes
remain unknown; reflection-sensitive arbitrary JavaScript is outside this
diagnostic pure generated-code domain. Archived C observations are not acquisition support for current backends. Instrumented artifacts are diagnostic copies;
original target files and production APIs receive no wrapper or caller checks.

The JavaScript producer preserves receiver/property/argument evaluation once and
method `this` binding. Recursive AST rendering preserves nested receiver and argument instrumentation,
including chained factories, parentheses, spread arguments and lexical await.
Unsupported optional/super operations remain explicitly unknown.
Counters reset before each untimed oracle invocation. Original and instrumented
complete outputs, input nonmutation, destination count/tail, and prior returned
values are compared. Caller ingress,
readback/consumer loops and setup must be separately acquired and bound before
pricing a benchmark boundary that includes them. Rust physical acquisition is
currently unavailable. Actual GPU host phase counters can be represented, while
uninstrumented shader/library traversal and allocation remain explicitly unknown;
a phase descriptor or capacity is never substituted for executed work.

Acquisition executes the exact fixture and observes its output-dependent work.
This is offline diagnosis, not a cheap online predictor. Trace/oracle acquisition,
instrumentation and setup are excluded from fitted call timings and selector
speed claims. A new call without comparable exact evidence cannot reuse a trace
merely because its lists have the same lengths. No per-call tracing, value scan or
runtime model adaptation is enabled. Synthetic test prices only exercise the
interface; fewer loops/allocations do not alone establish lower elapsed time.

Engine40 freezes its exploratory training declaration separately from code. Its
corrected pre-observation protocol uses affine/compaction/scan at 64 and 8192;
all 512 cells and all other families remain outside fit. Predictions/coefficients
must freeze before heldout timing evaluation, with unsupported cells, losses,
low-rank features and unidentified coefficients retained. Engine39's source-only
13-component model failed broad heldout tests; these emitted-site features are a
new hypothesis, not evidence that the earlier losses disappeared.

The real-checker integration script in `tests/physical_selection_integration.py`
replays an existing generic indexed/padded zip endpoint through composed,
content-bound helpers. It uses synthetic prices, verifies complete outputs for
both emitted alternatives, replays the snapshot and exact emission, and checks
that modified artifacts and a false application do not promote a replacement.
The root selected-parity fixture independently rechecks this package before
running current portable lowerings; diagnostic metadata grants no authority.

The General40 captured-JS preparation extracts the actual frozen runner capture
and consume arrow expressions by AST (rejecting ambiguous/missing definitions).
It instruments both that source-bound adapter and each generated module, adding
actual args.map callback visits, typed.slice carrier events/byte payload, and
every returned-word consumer visit. This matches the benchmark captured-owned
or captured-value boundary; only resident input setup, the outer timer loop and
post-timer validation are excluded. Body-only smoke observations cannot be fit
against this complete boundary. Boundary runner/extractor/adapter/receipt bytes
are additional authenticated sidecar bindings.

Canonical publication remains separate. Knowledge's `import_target_work40.py`
prepares immutable candidate entries and standard measured observations without
writing the catalogue. Trace/timing records use the diagnostic semantics
`ink-target-work-measurement-v1`; frozen prices use `ink-target-work-prices-v1`.
Both are ordinary `definition` entries, distinct from semantic rewrite laws.
They carry exact core, selection, emitted artifact, fixture, instrumenter, trace,
label and freeze identities. Price entries retain the exact original JSON text,
so fractional nanosecond coefficients survive canonical storage without numeric
rounding. Measurement entries retain exact round-trip decimal sample strings;
the existing observation index receives its required rounded integer strings
with `peak_bytes: null`.

Discovering these definitions never admits a computation. The selector still
replays the ordinary checked selection from the explicitly supplied snapshot,
reemits the selected JavaScript and requires matching bytes. Price extraction
must validate `PhysicalPrices` after decoding the stored JSON. Physical metadata,
content identities and timing receipts provide neither correctness nor application
conditions. Missing comparable observations or unknown required components retain
the baseline; Rust and GPU work cannot be filled from C or JavaScript traces.

The General40 acquisition includes the exact captured JavaScript boundary:
arguments are copied using the frozen runner's `capture` expression, the generated
function runs, and the frozen `consume` expression reads every output word. The
adapter is an untimed diagnostic: outer timer iterations, setup, instrumentation
and oracle checks remain excluded. Native callback visits are measured where the
actual runner uses `Array.map`; typed input `slice` events and bytes are counted.
Carrier construction events are not V8 allocator calls, and JavaScript Array
storage bytes remain unknown. Native C body-only traces are a separate cohort and
cannot train the complete-call General40 model. Rust feature acquisition and
actual GPU phase evidence remain required before those cohorts can be priced.

Publication can additionally bind a general `--context` record. Its exact
contents and source identity accompany each diagnostic measurement and price,
with a separate diagnostic definition dependency. Acquisition limitations and
poor heldout results therefore remain attached to prices rather than only in an
external narrative. The context grants no proof, application or default-selection
authority. Frozen model and prediction bytes remain intact.

New sidecars include an `acquisition` map in their cohort, binding the exact
instrumenter, runner, parser and any boundary extraction/adapter sources. The
consumer checks these against authenticated bindings; price cohorts compare
them exactly. A collector change therefore cannot reuse prices trained on old
feature definitions. Historical observations without this map remain comparable
only to their historical cohorts, never newly produced observations. Fit prices
from the observation's emitted cohort rather than reconstructing it from labels.

Sidecar trace parsing and hashing use one bounded byte snapshot. Other provenance
files are hashed incrementally; later changes are still rejected on consumption.
Install the diagnostic parser reproducibly with
`npm ci --prefix knowledge/tools/js-instrumentation --ignore-scripts`.
